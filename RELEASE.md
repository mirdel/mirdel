# Release Process

This project publishes desktop builds from Git tags.

## Standard Release

1. Make sure the release commit is on `main`.

   ```bash
   git checkout main
   git pull
   ```

2. Update the desktop app version in `packages/desktop/package.json`.

   ```json
   {
     "version": "0.1.1"
   }
   ```

3. Update `CHANGELOG.md`.

   Add a release section that matches the desktop app version.

   ```md
   ## 0.1.1 - 2026-04-21

   ### Added

   - Added ...

   ### Fixed

   - Fixed ...
   ```

   Use the same section as the source for the GitHub Release notes.

   Before creating the release tag, replace `Unreleased` with the release date.

   ```md
   ## 0.1.1 - 2026-04-21
   ```

   After the release, start the next development section at the top of the
   changelog.

   ```md
   ## 0.1.2 - Unreleased
   ```

4. Commit the release changes.

   ```bash
   git add packages/desktop/package.json CHANGELOG.md CHANGELOG.zh-CN.md
   git commit -m "chore: release v0.1.1"
   git push origin main
   ```

5. Create and push a matching tag.

   ```bash
   git tag v0.1.1
   git push origin v0.1.1
   ```

6. GitHub Actions will run `Desktop Release Matrix` automatically.

   The workflow validates that the tag version matches `packages/desktop/package.json`.
   For example, tag `v0.1.1` requires `"version": "0.1.1"`.

7. On tag builds, `electron-builder` publishes release assets to GitHub Releases.

   Expected user-facing assets:

   - `Mirdel-<version>-mac-arm64.dmg` for Apple Silicon Macs
   - `Mirdel-<version>-mac-x64.dmg` for Intel Macs
   - `Mirdel-<version>-win-x64.exe` for Windows

   Expected update metadata:

   - `.zip` files for macOS auto-update
   - `.blockmap` files for differential updates
   - `.yml` files generated by `electron-builder`

8. The workflow merges the macOS update feed.

   The arm64 and x64 macOS builds both produce `latest-mac.yml`. After the
   matrix build completes, the workflow merges both zip entries into one
   `latest-mac.yml` and uploads it back to the GitHub Release with `--clobber`.

   This keeps GitHub Releases as the auto-update feed while allowing
   `electron-updater` to choose the matching macOS architecture.

9. Fill the GitHub Release notes from the matching `CHANGELOG.md` section.

   The GitHub Release body is the user-facing source for release notes and can
   later be displayed by the desktop app's auto-update UI.

10. Update and redeploy the website.

   The sibling `website` project uses its root `package.json` version to build
   the GitHub Release download links. After publishing the desktop release,
   update `/Users/sky.sun/Github/mirdel/website/package.json` to the same
   version, then redeploy the website so the public download buttons point at
   the new release assets.

## In-App Updates

The packaged desktop app uses GitHub Releases as the update feed.

- The app checks for updates automatically after startup.
- Available updates are downloaded in the background.
- Downloaded updates show a non-blocking entry in the sidebar and a restart
  action on the About page.
- If the user quits the app after an update is downloaded, the update installs
  on app quit.
- On the first launch after an upgrade, the app displays the matching version
  notes from the bundled changelog.

Keep both changelog files up to date before tagging a release:

- `CHANGELOG.md` for English
- `CHANGELOG.zh-CN.md` for Simplified Chinese and Traditional Chinese fallback

## Manual Workflow Runs

The `workflow_dispatch` trigger is for CI/package validation only.

Manual runs:

- build all desktop targets
- upload GitHub Actions artifacts
- do not publish to GitHub Releases

Use manual runs to verify build stability without creating release assets.

## Signing Status

Current CI builds are unsigned and not notarized.

This is acceptable for internal validation, but public distribution should add:

- macOS Developer ID signing
- macOS notarization
- Windows code signing, or a Microsoft Store distribution path

Do not re-enable `CSC_LINK`, `WIN_CSC_LINK`, or Apple notarization secrets until the required certificates and credentials are configured correctly.
