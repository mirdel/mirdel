# 消息分支及重新生成功能详解（方案2+ & 扁平化）

## 🎯 核心设计理念

### 简化原则
- **分支 = 新 Session**（类似 ChatGPT）
- **扁平化分支**：所有分支都在同一层级，避免嵌套
- **重新生成 = 树形分叉**（同一 parent 下多个子消息）
- **选择记录 = message_selections 表**
- **消息溯源**：记录消息的复制来源和共享状态

---

## 📦 数据库设计

### 表 1: `sessions` (会话表 - 扁平化方案 + 方案2+)

```sql
CREATE TABLE sessions (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  selected_model TEXT NOT NULL DEFAULT '__default__',
  scenario_id TEXT NOT NULL DEFAULT 'default-scenario',
  root_session_id TEXT,           -- 根会话ID（顶级主会话）
  parent_session_id TEXT,         -- 父会话ID（从哪个会话分叉的）
  fork_from_message_id TEXT,      -- 父会话中的分叉点消息ID
  fork_point_message_id TEXT,     -- 本会话中对应的消息ID
  first_new_message_id TEXT,      -- 本会话中第一条新消息ID
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  FOREIGN KEY (root_session_id) REFERENCES sessions(id) ON DELETE SET NULL,
  FOREIGN KEY (parent_session_id) REFERENCES sessions(id) ON DELETE SET NULL
);
```

**字段说明：**
- `root_session_id`:
  - `NULL` = 主会话
  - `有值` = 分支会话，指向顶级主会话
  - **所有分支（无论从哪里分叉）都指向同一个根会话**（扁平化）

- `parent_session_id`:
  - `NULL` = 主会话
  - `有值` = 从哪个会话分叉的（可以是主会话，也可以是其他分支）
  - **用于追溯分叉路径和构建总览树**

- `fork_from_message_id`:
  - 父会话中的分叉点消息ID
  - 用于追溯和总览显示

- `fork_point_message_id`:
  - 本会话中对应的分叉点消息ID（复制后的新ID）
  - 快速定位本会话的起点

- `first_new_message_id`:
  - 本会话中第一条新消息的ID
  - 用于快速定位分叉后的第一条独有消息

**扁平化示例：**
```typescript
主会话: {
  id: 's1',
  rootSessionId: null,
  parentSessionId: null
}

分支1（从主会话分叉）: {
  id: 's2',
  rootSessionId: 's1',     // 根是主会话
  parentSessionId: 's1',   // 父是主会话
  forkFromMessageId: 'a1'
}

分支2（从分支1分叉）: {
  id: 's3',
  rootSessionId: 's1',     // 🔑 根还是主会话（扁平化）
  parentSessionId: 's2',   // 父是分支1（用于追溯）
  forkFromMessageId: 'a4'  // 这是分支1中的消息ID
}
```

### 表 2: `messages` (消息表 - 方案2+)

```sql
CREATE TABLE messages (
  id TEXT PRIMARY KEY,
  session_id TEXT NOT NULL,
  role TEXT NOT NULL,
  content TEXT NOT NULL,
  selected_model TEXT,
  status TEXT NOT NULL,
  parent_id TEXT,              -- 构建树结构
  copied_from_message_id TEXT, -- 如果是复制的，记录原消息ID
  is_shared INTEGER DEFAULT 0, -- 是否是共享消息（分叉点之前的）
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  FOREIGN KEY (session_id) REFERENCES sessions(id) ON DELETE CASCADE
);
```

**新增字段说明：**
- `copied_from_message_id`:
  - 如果是复制的消息，记录原消息的ID（跨会话引用）
  - 用于消息溯源和总览树构建

- `is_shared`:
  - `0` = 独有消息（本会话新创建的）
  - `1` = 共享消息（从父会话复制的，分叉点之前的）
  - 用于快速过滤和总览显示

### 表 3: `message_selections` (消息选择记录表)

```sql
CREATE TABLE message_selections (
  session_id TEXT NOT NULL,
  parent_message_id TEXT NOT NULL,
  selected_child_id TEXT NOT NULL,
  updated_at INTEGER NOT NULL,
  PRIMARY KEY (session_id, parent_message_id)
);
```

**作用：** 记录"在每个位置，用户选择了哪条路径"

## 🔧 功能 1：重新生成

### 工作流程

**场景：消息 1 → 2 → 3**

1. **重新生成消息 2**
   - 创建新消息（id=m2-prime, parentId=m1）
   - 保存选择：`message_selections(session_id, m1, m2-prime)`
   - UI 显示：1 → 2'
   - 切换器：◀ 2/2 ▶

2. **继续发消息 4**
   - 创建消息 4（parentId=m2-prime）
   - 消息树：
     ```
     m1
     ├─ m2 → m3
     └─ m2' → m4
     ```
   - UI 显示：1 → 2' → 4

3. **切换到 variant 1/2**
   - 更新选择：`message_selections(session_id, m1, m2)`
   - 重新构建路径：m1 → m2 → m3
   - UI 显示：1 → 2 → 3

## 🌿 功能 2：消息分支（扁平化 + 方案2+）

### 工作流程

**场景：从消息 3 创建分支**

1. **创建新 Session**
   ```typescript
   const newSession = {
     id: 'session-2',
     title: '项目讨论 - 分支 1',
     rootSessionId: 'session-1',      // 根会话（扁平化）
     parentSessionId: 'session-1',    // 父会话
     forkFromMessageId: 'm3',         // 父会话中的分叉点
     forkPointMessageId: 'm3-new',    // 本会话中的分叉点
     firstNewMessageId: null          // 稍后填充
   }
   ```

2. **复制消息到分叉点**
   - 回溯到根：[m3, m2, m1]
   - 复制消息（新 ID，记录溯源）
   - 标记 `isShared = 1`（共享消息）
   - 记录 `copiedFromMessageId`
   - 复制 selections

3. **从分支1创建分支2**
   ```typescript
   // 场景：主会话 u1,a1,u2,a2
   //      分支1 u1',a1',u3,a3,u4,a4
   //      从分支1的a4创建分支2
   
   const branch2 = {
     id: 'session-3',
     rootSessionId: 'session-1',      // 🔑 还是指向主会话（扁平化）
     parentSessionId: 'session-2',    // 父是分支1
     forkFromMessageId: 'a4',         // 分支1中的a4
     forkPointMessageId: 'a4-new'     // 本会话中的a4
   }
   ```

4. **结果（扁平化显示）**
   ```
   主会话 (session-1): u1 → a1 → u2 → a2
   ├─ 分支1 (session-2): u1' → a1' → u3 → a3 → u4 → a4
   └─ 分支2 (session-3): u1'' → a1'' → u3' → a3' → u4' → a4' → u5 → a5
   
   注意：分支2不是分支1的"子分支"，而是和分支1平级
   ```

## 💻 核心算法

### A. 获取显示消息列表

```typescript
function getDisplayMessages(sessionId: string): Message[] {
  // 1. 获取所有根消息
  const rootMessages = getRootMessages(sessionId)
  
  const result: Message[] = []
  
  // 2. 对每个根消息递归构建路径
  for (const root of rootMessages) {
    result.push(root)
    buildPathFrom(sessionId, root.id, result)
  }
  
  return result
}

function buildPathFrom(
  sessionId: string,
  parentId: string,
  result: Message[]
): void {
  const children = getChildren(parentId)
  
  if (children.length === 0) {
    return  // 叶子节点
  }
  
  // 查找用户选择的子消息
  const selection = getMessageSelection(sessionId, parentId)
  
  let selectedChild: Message
  if (selection) {
    selectedChild = children.find(c => c.id === selection.selectedChildId)
  }
  
  if (!selectedChild) {
    // 默认选最新的
    selectedChild = children[children.length - 1]
  }
  
  result.push(selectedChild)
  buildPathFrom(sessionId, selectedChild.id, result)
}
```

### B. 获取 Variant 信息

```typescript
function getVariantInfo(sessionId: string, messageId: string) {
  const message = getMessage(messageId)
  
  // 获取所有兄弟消息（同一 parent 的同 role 消息）
  const siblings = getSiblings(messageId)
  
  if (siblings.length <= 1) {
    return null  // 没有 variants
  }
  
  const currentIndex = siblings.findIndex(s => s.id === messageId)
  
  return {
    total: siblings.length,
    current: currentIndex + 1,
    siblings
  }
}
```

### C. 切换 Variant

```typescript
function switchToVariant(params: {
  sessionId: string
  parentMessageId: string | null
  targetChildId: string
}) {
  // 保存选择
  if (parentMessageId) {
    saveMessageSelection({
      sessionId,
      parentMessageId,
      selectedChildId: targetChildId
    })
  }
  
  // 重新加载消息
  return getDisplayMessages(sessionId)
}
```
